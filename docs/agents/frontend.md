# Frontend (Angular 22)

Structure, rendering model, quality gates, resilience rules and conventions of `frontend/`.

_Detail moved out of [`AGENTS.md`](../../AGENTS.md); the text is unchanged._

- **Frontend**: Angular 22 / TypeScript / Tailwind CSS — `frontend/`
  - Entry: `frontend/src/main.ts`; shell: `frontend/src/app/app.ts` (router-outlet + session bootstrap only).
  - Features: `features/landing/*` (guest landing, **eager** route `''`: lazy, its chunk and the booking/forms chunks it imports were discovered only after `main.js` ran — two extra round trips before first paint; `initial` budget 470/500 kB (was 550/600 before §63, lowered so a regression fails the build), currently 441 kB; **prerendered at build time** — `outputMode: "static"`, `app.routes.server.ts` (`''` Prerender, `**` Client), incremental hydration with event replay, lookbook/FAQ/post-booking `@defer (hydrate on idle)` and the booking wizard `@defer (on idle; hydrate on idle)` — it stays prerendered, but its chunk and Signal Forms left the eager `main.js` (545 → 441 kB raw, 147 → 122 kB transfer, §63); the landing page must therefore NOT import `BookingStore` (that static import pulls Signal Forms back in; an ESLint `no-restricted-imports` rule on `features/landing/**` enforces it) — the lookbook hand-off goes through `LookbookSelectionBus`. Do **not** change the wizard to `hydrate on interaction`: the block is not self-contained (the lookbook drives it from outside, its service list must render before anyone touches it, and the guest page's shared `.alert-error`/`.alert-success` live in its template), and four `appointment-flow` e2e tests fail; nothing may call the backend while prerendering: stores/session/CSRF bootstrap check `isServerRender()` and `PrerenderBackend` fails stray requests; slow-4G FCP 2.1 → 1.0 s, §60), `features/booking/*` (`booking.store.ts` wizard state machine + `booking-wizard.*`), `features/admin/*` (dashboard shell + 4 tab components), `features/customer/*`. Cross-cutting API clients live in `core/api/*` (`AuthApi`, `CatalogApi`, `BarbersApi`, `AppointmentsApi`, `NotificationsApi`, `ReviewsApi`); guest endpoints are marked with the `PUBLIC_REQUEST` HttpContextToken (never by URL matching) so a public 401 cannot clear the session. Session events flow through `core/session-events.ts`, not a DOM CustomEvent.
  - Contracts: request **and response** payloads are validated at runtime with the shared zod schemas (`@taskflow/schemas` → `shared/schemas/`), including SSE events and `httpResource` responses via `parse`. Add/update schemas there before wiring a new endpoint. The schemas use **`zod/mini`** (functional API: `string().check(trim(), minLength(1, msg), email(msg))`, `optional(x)`, `array(x)`, `pipe(nullish(string()), transform(...))`) — classic `zod` put ~112 KiB into `main.js`; keep the check order (it decides `issues[0]`) and export list schemas (`*ListSchema`) instead of calling `.array()` in the apps.
  - Quality gates: `npm run lint` = `theme:check` + ESLint (angular-eslint recommended + template a11y) + strict `tsc` for app & spec projects; `tsconfig.json` has `strict`, `noUncheckedIndexedAccess`, `noUnusedLocals/Parameters`. Unit tests enforce `coverageThresholds` in `angular.json` (65/66/52/66), so cover new stores/components. `lint` and `format:check` keep ESLint (content strategy), `tsc` incremental and Prettier caches in `node_modules/.cache/` (warm lint ~10 s → ~5 s); no ESLint rule uses type information, so a cached result cannot go stale through another file. Tailwind scans `src/` only (`@import 'tailwindcss' source('./')`, specs excluded). `ng serve` excludes `@taskflow/schemas` from Vite prebundling (its extensionless TS imports crashed the optimizer). Angular 22 defaults apply: no `.browserslistrc` (Angular's baseline, incl. iOS/Safari 17/18), no change-detection provider and no explicit `OnPush` (zoneless + OnPush are the defaults). Opening the login modal prefetches the dashboard chunks (`dashboard-loaders.ts`, shared with `app.routes.ts`). The image's CSP authorizes every inline script of both shells by sha384 (`frontend/Dockerfile` pins the per-page inventory — import maps, event-dispatch contract and bootstrap — and fails the build on drift; `e2e/csp.spec.ts` re-hashes the served pages); update both when Angular changes what it inlines. Design tokens are generated from `src/theme/tokens.json` (`npm run theme:build`, checked in CI) — edit the JSON, not `tokens.generated.css`. `e2e/a11y.spec.ts` gates axe serious/critical violations. `theme:build`/`theme:check` also enforce WCAG AA contrast for `src/theme/tokens.json` (`scripts/theme-contrast.mjs`: text tokens ≥4.5:1 on bg/card/surface/inputBg/dark, `text.dark` on gold fills, `gold.dark` ≥3:1 non-text); `mobile/__tests__/theme.test.ts` asserts the same pairs for the mobile tokens (`text.muted` is `#8a8a93` on both platforms). The booking stepper is a WAI-ARIA tablist with manual activation (arrows/Home/End move focus, Enter/Space activate; gated steps stay focusable with `aria-disabled`, see `BookingStore.isStepReachable`); form errors (`role="alert"`) render only after `touched()` or a submit attempt, and a failed submit focuses the first invalid field.
  - Resilience: never read an `httpResource().value` directly in a computed/template — Angular 22 **throws `ResourceValueError` while the resource is in error**, `defaultValue` or not. Stores expose safe lists via `safeResourceValue`/`refreshResource` (`core/resource-utils.ts`) and templates gate on `error()`/`hasValue()`. `logout()` keeps the user signed in until the server answers 2xx (403 → refetch `/auth/csrf` and retry once); a 401 for a signed-in user navigates to `/` with a "session expired" notice and opens the login modal (`SessionEvents.sessionEnded` also resets the per-user stores). `me()`/`logout()` are `PUBLIC_REQUEST`. Customers book at `/customer/book` (guarded); the wizard disables passed slots (`now`/`today` signals refreshed on entry, visibility change and at midnight), and a busy-slots failure blocks step 3 (it is *unknown*, never "all free"). `AdminEventsService` reconnects with backoff and forces a full reload after every (re)connect. `CANCELLED` is a first-class status in the UI.
- **Frontend uses Angular 22 Signals** (no Zone.js digest loops). Styles use Tailwind with custom `gold`/`obsidian` color palette from `frontend/src/theme/tokens.json`.
- **Prettier** is the formatter (100 char width, single quotes). Run `npx prettier --write <file>` in `frontend/`.
