# Frontend (Angular 22)

Structure, rendering model, quality gates, resilience rules and conventions of `frontend/`.

_Detail moved out of [`AGENTS.md`](../../AGENTS.md); the text is unchanged._

- **Frontend**: Angular 22 / TypeScript / Tailwind CSS — `frontend/`
  - Layout (feature-first, per the Angular style guide; ADR-022 is the backend counterpart): `src/app/core/` is the app-wide layer (API clients in `core/api`, `core/auth` for `AuthState`/guard/interceptor and the dashboards' `injectSignOut()`, `core/ui/flash-messages.ts` for the app-wide banner, `core/time-utils.ts`, and the stores several features share, grouped by domain: `core/customer`, `core/catalog`, `core/reviews`); `src/app/features/<name>/` holds everything one feature owns, including its stores and child components (`features/landing/lookbook`, `features/booking/steps`, `features/booking/stylist-card`, `features/admin/appointment.store.ts`, `features/admin/barber.store.ts`, …). A store used by exactly one feature lives in that feature; used by two or more it goes to `core/<domain>/`. `core` must not import `features` (ESLint `no-restricted-imports`); `dashboard-loaders.ts` stays at the app root next to `app.routes.ts` because it is the lazy-loading bridge. Specs sit next to their subject. Template-only members are `protected` (`readonly` for signals); a member stays public when a spec or another class uses it. `types/api.ts` is generated from `api/openapi.json` (`npm run sync:api-types`) and keeps its path. Moving a file means updating `src/component-map.json`; `npm run check:component-map` fails on a stale path.
  - Entry: `frontend/src/main.ts`; shell: `frontend/src/app/app.ts` (router-outlet + session bootstrap only).
  - Features: `features/landing/*` (guest landing, **eager** route `''`: lazy, its chunk and the booking/forms chunks it imports were discovered only after `main.js` ran — two extra round trips before first paint; `initial` budget 450/470 kB (was 550/600 before §63 and 470/500 before §65, lowered so a regression fails the build), 443.1 kB since Angular 22.3 (§83), 445.9 kB once the landing page showed the real client ratings (`ReviewStore` moved into `main.js`, +2.8 kB raw / +0.4 kB transfer), currently 448.6 kB with the `core/ui` building blocks (`Icon`, `Button` and the landing page's eight icons); no `@angular/common` pipes or `NgClass`/`CommonModule` (ESLint `no-restricted-imports`; format with `core/format.ts`): the router puts that package's shared chunk into the initial bundle, so they shipped ~22 kB to every guest page; **prerendered at build time** — `outputMode: "static"`, `app.routes.server.ts` (`''` Prerender, `**` Client), incremental hydration with event replay, lookbook/FAQ/post-booking `@defer (hydrate on idle)` and the booking wizard `@defer (on idle; hydrate on idle)` — it stays prerendered, but its chunk and Signal Forms left the eager `main.js` (545 → 441 kB raw, 147 → 122 kB transfer, §63); the landing page must therefore NOT import `BookingStore` (that static import pulls Signal Forms back in; an ESLint `no-restricted-imports` rule on `features/landing/**` enforces it) — the lookbook hand-off goes through `LookbookSelectionBus`. Do **not** change the wizard to `hydrate on interaction`: the block is not self-contained (the lookbook drives it from outside, its service list must render before anyone touches it, and the guest page's shared `.alert-error`/`.alert-success` live in its template), and four `appointment-flow` e2e tests fail; nothing may call the backend while prerendering: stores/session/CSRF bootstrap check `isServerRender()` and `PrerenderBackend` fails stray requests; slow-4G FCP 2.1 → 1.0 s, §60), `features/booking/*` (`booking.store.ts` wizard state machine: Signal Form, step navigation, availability, submission; `booking-calendar.ts` the calendar rules as pure functions that take "now" — closed weekdays, the 7-day carousel, past/taken slots — with their own spec; `booking-wizard.*` the shell: stepper, focus management, banner, footer, receipt; `steps/*` one component per step — service, stylist, date & time, contact — each injecting `BookingStore` directly and rendering its own `#step-panel-N` tabpanel inside a `display: contents` host, so the DOM the e2e/axe suites select on is the one the inline template had), `features/admin/*` (dashboard shell + 4 tab components; `appointment.store.ts` is the owner's appointment list — page, filter, debounced search, page clamp, refresh tick), `features/customer/*` (portal and `/customer/book`). Cross-cutting API clients live in `core/api/*` (`AuthApi`, `CatalogApi`, `BarbersApi`, `AppointmentsApi`, `NotificationsApi`, `ReviewsApi`); guest endpoints are marked with the `PUBLIC_REQUEST` HttpContextToken (never by URL matching) so a public 401 cannot clear the session. Session events flow through `core/session-events.ts`, not a DOM CustomEvent (`sessionEnded` on logout/expiry, `sessionStarted` on sign-in). The one alert banner (`errorMessage`/`successMessage`, `showSuccess` auto-dismisses after 4.5 s, `reportActionError` skips a 401) is `FlashMessages` (`core/ui`): the wizard, the guest cancel/review forms, the landing page and both dashboards write it, and it clears itself on both session events — never clear it by hand on login. Per-form busy flags stay local to their form (`isSubmitting` belongs to `BookingStore`).
  - Contracts: request **and response** payloads are validated at runtime with the shared zod schemas (`@taskflow/schemas` → `shared/schemas/`), including SSE events and `httpResource` responses via `parse`. Add/update schemas there before wiring a new endpoint. The schemas use **`zod/mini`** (functional API: `string().check(trim(), minLength(1, msg), email(msg))`, `optional(x)`, `array(x)`, `pipe(nullish(string()), transform(...))`) — classic `zod` put ~112 KiB into `main.js`; keep the check order (it decides `issues[0]`) and export list schemas (`*ListSchema`) instead of calling `.array()` in the apps.
  - Quality gates: `npm run lint` = `theme:check` + ESLint (angular-eslint recommended + template a11y, cached) + a type-aware ESLint pass (`eslint.typed.config.mjs`: `no-floating-promises`, `no-misused-promises`; uncached, ~5 s) + strict `tsc` for app & spec projects; `tsconfig.json` has `strict`, `noUncheckedIndexedAccess`, `noUnusedLocals/Parameters`. Unit tests enforce `coverageThresholds` in `angular.json` (65/66/52/66), so cover new stores/components. `lint` and `format:check` keep ESLint (content strategy), `tsc` incremental and Prettier caches in `node_modules/.cache/` (warm lint ~10 s → ~5 s); no rule in the cached ESLint pass uses type information, so a cached result cannot go stale through another file; type-aware rules go into `eslint.typed.config.mjs`, which always runs in full (CI's ESLint cache is empty anyway: `node_modules` is cached before lint runs). Mark a deliberate fire-and-forget Promise with `void` (e.g. `void this.router.navigateByUrl(…)`), otherwise await it (§84). Tailwind scans `src/` only (`@import 'tailwindcss' source('./')`, specs excluded). `ng serve` excludes `@taskflow/schemas` from Vite prebundling (its extensionless TS imports crashed the optimizer). Angular 22 defaults apply: no `.browserslistrc` (Angular's baseline, incl. iOS/Safari 17/18), no change-detection provider and no explicit `OnPush` (zoneless + OnPush are the defaults). Opening the login modal prefetches the dashboard chunks (`dashboard-loaders.ts`, shared with `app.routes.ts`). The image's CSP authorizes every inline script of both shells by sha384 (`frontend/Dockerfile` pins the per-page inventory — import maps, event-dispatch contract and bootstrap — and fails the build on drift; `e2e/csp.spec.ts` re-hashes the served pages); update both when Angular changes what it inlines. `style-src` has no `'unsafe-inline'` either (#224): never write a `style="…"` attribute or a `[style.*]` binding in a template that is prerendered (both end up as markup the browser refuses; Angular also applies static `style` attributes through `setAttribute`), use a class instead: a Tailwind utility, which beats the shared component classes (`app.css` keeps `.btn`/`.card`/`.form-control`/`.modal-card`/… in `@layer components`, so `btn btn-submit py-2 px-6` gets that padding). Browser-only `[style.*]` bindings are fine (CSSOM). The one runtime `<style>` the CDK injects (`.cdk-visually-hidden`, `cdkTrapFocus`) is hashed from its chunk with a pinned inventory (`EXPECTED_STYLES` in `frontend/Dockerfile`); `e2e/csp.spec.ts` fails on any `securitypolicyviolation`. Design tokens are generated from `src/theme/tokens.json` (`npm run theme:build`, checked in CI) — edit the JSON, not `tokens.generated.css`. `e2e/a11y.spec.ts` gates axe serious/critical violations. `theme:build`/`theme:check` also enforce WCAG AA contrast for `src/theme/tokens.json` (`scripts/theme-contrast.mjs`: text tokens ≥4.5:1 on bg/card/surface/inputBg/dark, `text.dark` on gold fills, `gold.dark` ≥3:1 non-text); `mobile/__tests__/theme.test.ts` asserts the same pairs for the mobile tokens (`text.muted` is `#8a8a93` on both platforms). The booking stepper is a WAI-ARIA tablist with manual activation (arrows/Home/End move focus, Enter/Space activate; gated steps stay focusable with `aria-disabled`, see `BookingStore.isStepReachable`); form errors (`role="alert"`) render only after `touched()` or a submit attempt, and a failed submit focuses the first invalid field.
  - Bundle budgets (`angular.json`): since Angular 22.3 the build's chunk optimizer folds every module the initial page loads into `main.js` (fewer initial round trips; lazy routes stay split), so `main.js` is ~400 kB raw instead of ~120 kB plus three initial chunks. The per-file `any` budget is 420/450 kB to fit it; the `initial` budget (450/470 kB) is what bounds first-load size. Trade-off: framework code is no longer a separately cached chunk, so every `main.js` change re-downloads it (§83).
  - Resilience: never read an `httpResource().value` directly in a computed/template — Angular 22 **throws `ResourceValueError` while the resource is in error**, `defaultValue` or not. Stores expose safe lists via `safeResourceValue`/`refreshResource` (`core/resource-utils.ts`) and templates gate on `error()`/`hasValue()`. `logout()` keeps the user signed in until the server answers 2xx (403 → refetch `/auth/csrf` and retry once); a 401 for a signed-in user navigates to `/` with a "session expired" notice and opens the login modal (`SessionEvents.sessionEnded` also resets the per-user stores). `me()`/`logout()` are `PUBLIC_REQUEST`. Customers book at `/customer/book` (guarded); the wizard disables passed slots (`now`/`today` signals refreshed on entry, visibility change and at midnight), and a busy-slots failure blocks step 3 (it is *unknown*, never "all free"). Busy slots are an `httpResource` keyed on the barber (the "No Preference" sentinel is sent as is), date and service: changing one cancels the lookup in flight, a closed day or an empty date is never looked up, the request reads per-field `computed`s so typing contact details never refetches, entering step 3 reloads, and Retry/a stale slot at submit restart it via `refreshResource`. Specs must `TestBed.tick()` before expecting that request and answer it before `await fixture.whenStable()` (an open lookup is a pending task). `AdminEventsService` reconnects with backoff and forces a full reload after every (re)connect; the dashboard turns events into `AppointmentStore.refreshWhenIdle()`, which lets a load in flight finish and follows it with one more (restarting on every event could keep the list from ever settling), while user actions keep `refresh()`. Every HttpClient/`httpResource` request is bounded by `core/http/request-timeout.interceptor.ts` (10 s like mobile, above the server's ~9 s worst case; a request's own `timeout` wins); an expired request fails as an `HttpErrorResponse` with status 0, i.e. the "cannot reach the server" path. The SSE stream is an `EventSource` and not affected. The only rxjs `retry` is the boot-time CSRF fetch. `CANCELLED` is a first-class status in the UI.
  - Session renewal (ADR-023): `authInterceptor` answers a protected 401 with one `AuthState.renewSession()` (single flight, CSRF refetch on 403) and one replay (`SESSION_RENEWED` context token), but only while the readable `taskflow_session` hint cookie exists (`core/auth/session-hint.ts`); `AuthState.bootstrap()` does the same for a boot-time `/auth/me` 401, restoring the principal without `sessionStarted`. Only a renewal answered with 401 ends the session (`notifyUnauthorized`); offline, a timeout or a 5xx keeps it and reaches the caller as that error. Every request is fenced by `SessionEvents.epoch()` (moved by `notifySessionStarted`/`notifySessionEnded`, not by a renewal): a 401 sent under an older epoch is ignored, and a renewal that a login or logout overtook fails with `SessionChangedError` (no principal applied, no replay, no sign-out). Specs that need it set `document.cookie = 'taskflow_session=1'` and must remove it afterwards.
  - Reference data after admin writes: `ReferenceDataEvents.rosterChanged` (core) makes `PublicBarberStore` and `ShopClock` refetch after a barber is added or a weekly schedule saved (the responses are `no-cache`, so a refetch reaches the server); the catalog store is updated directly (`ServiceCatalogStore.upsertService/removeService`).
  - Shared UI building blocks in `core/ui/` (each with a spec): `Button` (`button[appButton]`/`a[appButton]`, variants `primary` (default), `secondary`, `danger`; it only adds the `.btn*` classes, so spacing stays a utility on the element, and a template that forgets to import it keeps a plain unstyled button without any compiler error), `Alert` (`<app-alert tone="error|warning|success|info" dismissible (dismissed)>`, errors are `role="alert"`, the rest a polite `role="status"`; the host keeps the `alert alert-<tone>` classes the e2e suites select on; an action goes in as `<button alertAction>`), `EmptyState` (`kind="empty|loading|error"`, title, description, projected actions), `StatusBadge` (appointment and outbox statuses, `[overdue]`; tones are `.tone-*` classes in `app.css`), `SegmentedControl` (a labelled `role="group"` of `aria-pressed` buttons; use tabs for switching panels), `PageHeader` (the signed-in pages' `<h1>`, no entrance animation) and `Icon` (`<app-icon [icon]="calendarIcon">`, decorative, 1em unless a size utility is set). Icons are Lucide (ISC), one module per icon in `core/ui/icons/<name>.ts`, each a single merged SVG path; import them one by one: a shared icons file or a barrel puts every icon into `main.js` (esbuild keeps a module in one chunk), which cost 6 kB of the initial budget. Also in `core/ui/`: `ReschedulePicker` (customer portal and guest post-booking actions; takes the booking's `publicId`, plus the `email` for a guest, and greys out the server's `…/availability` answer for that booking, showing the server's reason on error; the guest form fixes `{publicId, email}` when the picker opens, and editing either field closes it) and `download.ts` (`downloadTextFile`: anchor in the document, object URL revoked later, `false` where unsupported). Telemetry (`core/telemetry`, off by default via `CLIENT_TELEMETRY_OPTIONS`) sends with `fetch(..., { keepalive: true, credentials: 'omit' })`; errors reach it only through `TelemetryErrorHandler` (no own window listeners), page-load vitals are attributed to the first completed navigation.
  - Prerendered `@defer` blocks: a block that only reacts to clicks and keys (lookbook, FAQ) uses `prefetch on idle; hydrate on interaction`, not `hydrate on idle`. Angular replays a click made before `main.js` has run only once the app is stable; a block that hydrated on idle has dropped its replay hooks by then and the click is lost, while a block that is still dehydrated is hydrated by the replayed click (BENCHMARKS §70). A block that is not self-contained (the wizard: driven by the lookbook, owns the shared alert banners) or holds form fields (post-booking actions) keeps `hydrate on idle`; clicks on those before the page has loaded are not replayed. `e2e/early-interaction.spec.ts` delays the scripts and clicks at once; give a new interactive prerendered block a case there.
  - Prerendered first paint: content that arrives after it (shop info, catalog) holds its space from the start, invisibly or as a placeholder of the final height. The open/closed badge used to appear only once `/public/shop` answered; below 430 px the nav wraps around it, so the page moved down 28 px (CLS 0.09). It is now always rendered, `invisible` until the hours are known. Above-the-fold text gets no entrance animation: Chrome does not report a transparent element as LCP, so the hero's 250 ms fade-in moved LCP to the font swap (1.6 s instead of 0.7 s on slow 4G). The same holds for the signed-in pages: the admin dashboard, customer portal and booking page used to fade in as a whole, which left their FCP and LCP to the first paint after the API answered (BENCHMARKS §73). Fades that follow an interaction (modals, alerts, wizard steps, admin tabs) are fine. A secondary button below fields that validate on blur (the login modal's mode toggle, the wizard's Back) takes `(mousedown)="$event.preventDefault()"`: otherwise the press blurs the field, its message moves the button, and the release misses it (BENCHMARKS §74, `e2e/lost-clicks.spec.ts`). Both are measured in BENCHMARKS §72/§73 and guarded by `e2e/landing-stability.spec.ts`.
- **Frontend uses Angular 22 Signals** (no Zone.js digest loops). Styles use Tailwind; colours, radii, shadows and the font come from `shared/theme/tokens.json` (`@taskflow/theme`, also the mobile app's tokens), whose `semantic` names (`page`, `surface`, `raised`, `fg`, `fg-muted`, `accent`, `accent-tint`, `danger`, …) are the only colours generated into the theme (`bg-surface`, `text-accent`, `var(--color-accent)`); the raw `colors` palette there is what the contrast check reads. `app.css` defines no colours of its own and has no `!important`; its component classes are in `@layer components`, so a utility on the same element wins.
- **Prettier** is the formatter (100 char width, single quotes). Run `npx prettier --write <file>` in `frontend/`.
