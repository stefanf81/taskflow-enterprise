# Gotchas and testing notes

Things that bite: which Gradle task needs Docker, guard tests, cache/header alignment and the offline-startup rule.

_Detail moved out of [`AGENTS.md`](../../AGENTS.md); the text is unchanged._

- **Testcontainers** start the PostgreSQL server of every test JVM. The default
  `test` task gives each Spring context its own database, cloned from a
  Flyway-migrated template (`testsupport/PostgresTestDatabases`); the tagged
  `testcontainersTest` task creates its own schemas and databases. Both need
  Docker, or `TASKFLOW_TEST_POSTGRES_URL` (plus `_USER`/`_PASSWORD`) naming a
  server. H2 is left to `bootRun`, the offline AOT-cache training and
  `H2DefaultProfileSmokeTest`, which pins it.
- **Module boundaries** are enforced by Spring Modulith (`ModularityTest`, ADR-022): each module's `package-info.java` lists `allowedDependencies`, and only a module's public root-package types are its API. A new cross-module call needs the dependency declared there; hand other modules snapshots (`AppointmentDetails`), never the `Appointment` entity; keep controllers, `*Impl` classes and glue package-private. `ArchitectureTest` (ArchUnit) only keeps the coding-standard rules. Each module has an `@ApplicationModuleTest` (`*ModuleTest`) that boots just that module; give it its own uniquely named fixtures, because a Spring context's database is shared with every other test class that reuses that cached context, and some of them delete the seed rows.
## Gotchas

- `./gradlew test` runs on PostgreSQL (BENCHMARKS.md §85): it needs Docker, or
  `TASKFLOW_TEST_POSTGRES_URL` pointing at a server where the user may create
  databases. `./gradlew testcontainersTest` runs the tagged PostgreSQL suite.
  A test that must run on H2 pins `spring.datasource.url` in
  `@SpringBootTest(properties = …)`.
- Full `./verify.sh` also requires `psql` on `PATH` for the migration-preparation script tests. Homebrew's `libpq` is keg-only: use `PATH="$(brew --prefix libpq)/bin:$PATH" ./verify.sh` after installing it.
- On macOS Rancher Desktop (`unix://…/.rd/docker.sock`), `verify.sh` sets `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock` for Ryuk unless already explicitly set. Direct Gradle invocations need that environment override too; do not disable Ryuk or change the host Docker endpoint to fix the VM mount.
- Refresh `api/openapi.json` only with `npm run api:spec:update` against a running backend (`./gradlew bootRun`). A document dumped from a test context (MockMvc) lists `servers` as `http://localhost` instead of `http://localhost:8080`, and CI's OpenAPI Contract job compares the live document exactly; `verify.sh` does not catch it.
- `./gradlew check` does not run OWASP dependency checking. Run `./gradlew dependencyCheckAnalyze` explicitly when needed (fails on CVSS >= 7).
- Container-config guards (`@Tag("container-config")`: `ContainerImageBenchmarkTest`, `GlibcTuningBenchmarkTest`, `ContainerConfigGuardTest`) are excluded from `test` and run in `containerConfigTest`, which declares the files they read as inputs. A new guard that reads another file must add it to that task's `inputs.files` (and, if it is a workflow, to CI's `docker_backend` filter).
- The `.env` file (from `.env.example`) is required by docker-compose and is git-ignored — copy `.env.example` to `.env` and adjust as needed. Change default passwords before production use.
- Frontend `dist/` and `node_modules/` are gitignored. Do not commit build artifacts.
- E2E tests (`npm run e2e`) start their own dev server — don't run `npm start` separately when running e2e.
- **PostgreSQL major upgrades**: the official image (18+) keeps its data in `/var/lib/postgresql/<major>/docker` and refuses to start when the volume holds another major's directory (`there appears to be PostgreSQL data in: /var/lib/postgresql/18/docker`). After a major bump of the compose image, remove the local volume once (`docker compose down`, then `docker volume rm "$(basename "$PWD")_pgdata"`); Flyway rebuilds the schema and the reference data. Production is upgraded by the dump-and-restore init containers in `homelab/TF` (`gitops/apps/taskflow/postgres-db.yaml`), never by changing the tag alone. The pins are `docker-compose.yml`, `ci.yml`, `dast.yml` and `docs/deployment/booking-time-migration-presync-job.yaml`; Renovate tracks all four and holds the major in `.github/renovate.json`. The PostgreSQL tests take their image from `docker-compose.yml` (`PostgresTestServer.IMAGE`): Renovate ignores `src/test`, so never name an image in a test.
- **PgBouncer ceiling**: The current deployment is one replica against PostgreSQL `max_connections=50`. Security and cache state is replica-safe (`app.state.store=redis`), but do not add replicas until admin SSE appointment events are distributed and PgBouncer transaction pooling (or pool × replicas < 50) is in place.
- **Cache eviction is verified, not assumed**: `barbers`/`publicBarbers`/`services` (`10 m`) & `busySlots` (`2 m`) use `@CacheEvict(allEntries=true)` on `create/update/delete`; `ReferenceDataCacheBenchmarkTest` asserts `200→201` after mutation. Don't add L2/Hib query cache without re-testing.
- **Cache-Control ↔ @Cacheable alignment**: Changing tiered headers (`no-cache, public` catalog/barbers/shop, which admins edit from both clients; `no-cache` busySlots/ratings; `no-store` admin and customer lists) must keep `10 m` `@Cacheable`, its after-commit invalidation and `ShallowEtagHeaderFilter` (GET-only) in sync — otherwise `304`/`TTL` mismatches cause stale or over-fetch. A `max-age` on admin-editable data makes the editor's own refetch show the old list.
- **Client HTTP caches obey `max-age`, not query invalidation**: the browser and the mobile app's native stack (OkHttp 10 MB disk cache on Android, shared NSURLCache on iOS) answer a fresh response from disk, so TanStack `invalidateQueries` / `httpResource.reload()` never reaches the server. Anything a client refetches after its own mutation (busy slots after a booking, ratings after a review) must be `no-cache` (ETag keeps it a `304`); `busySlots` used to be `30 s private` and showed a just-booked slot as free. Personal data must be `no-store` — `no-cache` still writes it to disk, where it outlives logout (BENCHMARKS.md §44).
- **HEALTHCHECK divergence**: Don't add `HEALTHCHECK` to the Dockerfile's `prod` target or to a stage it inherits from (`runtime`, `java-base`) — K8s `livenessProbe` owns prod; the `local` target keeps it for `docker run` & `depends_on: service_healthy` (`ContainerConfigGuardTest` asserts presence/absence).
- **Mobile query tuning**: `staleTime 0→60_000` cuts refetch ~50% — but raising further risks showing stale `DENIED` slots; the `busySlots` response is `no-cache` (revalidated every time), so an invalidation always reaches the server. `timeout 10000` exceeds the server's worst case for **one** query (Hikari `connection-timeout` 4 s to get a connection + JPA query timeout 5 s; `validation-timeout=1000` caps how far a dead-connection check can overrun the pool wait, the 5 s default could add 5 s) — don't lower it below that, and keep `validation-timeout` small when changing either. These are per-phase limits, not a whole-request deadline: a request that runs several queries (or waits on Redis or a lock) can still outlast the client's 10 s, and nginx's `proxy_read_timeout 30s` only bounds silence between reads.
- **UseContainerSupport is explicit**: `JAVA_TOOL_OPTIONS` carries `UseContainerSupport` + `HeapDumpOnOutOfMemoryError` + `gc.log` in both `docker-compose.yml` and `homelab/TF` — sizing lives in env, not image CMD (last-wins precedence bug).
- **Default-profile startup must stay offline**: the AOT cache training run boots the real app under `--network=none`, so a startup-time call to an external service (or a bean that needs PostgreSQL/Redis to refresh) fails the image build. The `prod` target has no `curl`/`wget` — K8s probes must be `httpGet`, and debugging uses `kubectl debug`.
- **Web-font layout shifts depend on the measuring machine's fonts**: where Inter is installed as a system font (the cloud dev container is one), fontconfig maps `system-ui` to it, so the landing page's fallback looks like Inter and the font swap moves nothing; CI runners and most visitors swap from a wider fallback (CLS 0.02–0.03 at 390 px with DejaVu Sans). Measure CLS with Inter hidden (a `FONTCONFIG_FILE` with `<rejectfont><glob>*Inter*</glob></rejectfont>`), and keep font-swap shifts out of e2e assertions that are about something else (BENCHMARKS §72).
