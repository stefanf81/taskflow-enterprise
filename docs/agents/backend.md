# Backend architecture, performance and caching

Spring Boot / Java 25 package layout, runtime tunings, the Redis cache stack, async executor, slot index and Cache-Control rules.

_Detail moved out of [`AGENTS.md`](../../AGENTS.md); the text is unchanged._

- **Backend**: Spring Boot 4.1.2 / OpenJDK 25 (LTS) / Gradle — `src/main/java/com/example/taskflow/`
  - High-Performance Tunings: Container-portable heap sizing (deployment-owned via `JAVA_TOOL_OPTIONS`), Virtual Threads explicitly ENABLED (`spring.threads.virtual.enabled=true`, with `spring.main.keep-alive=true`; see BENCHMARKS.md §32), Jackson 3, Lazy Connection Fetching, Asynchronous Logging, OpenTelemetry 10% sampling, Redis-backed caching (Spring Cache abstraction) + **P0–P2**: bounded async executor `AsyncConfig` (`core=8 max=64 queue=100 CallerRunsPolicy`, `taskflow-async-` 30 s graceful) replaces unbounded default (BENCHMARKS.md §38); tiered `Cache-Control` + `ShallowEtagHeaderFilter` (GET-only) + Nginx `keepalive 64` & immutable hashed assets (`public, immutable, max-age=15552000` 6 M) (§42/§44); Micrometer histograms `p50/p95/p99` + `slo 50/100/200ms` + `percentiles-histogram` at `/actuator/prometheus` (§46); explicit `-XX:+UseContainerSupport` + heap dump + GC log on the `backend-diagnostics` volume (`/var/log/taskflow`, §43/§60); mobile `queryClient` `staleTime 60_000`/`gcTime 5*60_000` + `timeout 10000` (§45); PgBouncer ceiling docs Hikari `25/25` (fixed-size), `pool×replicas<50` (`max_connections=50`, mirrored in compose), `>2→PgBouncer transaction` (§50); Lookbook `FlatList scrollEnabled={false}`→`map` virtualization fix (§49).

- **DB**: SQL Flyway migrations in `src/main/resources/db/migration/`; Java-based migrations in `src/main/java/db/migration/`
- **DB**: H2 in dev/test, PostgreSQL in prod (docker-compose / K8s). Flyway handles migrations — never use `ddl-auto=update`. All profiles use `ddl-auto=validate`.
- **OSIV is off** (`spring.jpa.open-in-view=false`) — connections return to Hikari pool immediately after service methods.
- **Bounded Async Executor (P0-1 §38)**: `core/AsyncConfig.java` replaces Spring's unbounded `@EnableAsync` default (`core=8 max=Integer.MAX_VALUE queue=Integer.MAX_VALUE`) with bounded `ThreadPoolTaskExecutor` `core=8 max=64 queue=100 CallerRunsPolicy` (`taskflow-async-` 30 s graceful) — burst backpressures caller instead of OOMing the 1.25 GiB heap.
- **Partial Unique Slot Index (P0-4 V21/V25 §41)**: `db/migration/V21__fix_double_booking_index.java` introduces the PostgreSQL partial index `idx_appointment_slot_active ON appointments(barber_name, booking_date, booking_time) WHERE status IN ('PENDING','APPROVED')`, with a plain 4-column unique index (adding `status`) as V21's own H2 fallback. `V25__converge_appointment_slot_index.java` later reconciles both migration paths onto the same semantics and upgrades the H2 fallback to a generated-column emulation of the partial index (`active_slot_marker INTEGER AS (CASE WHEN status IN ('PENDING','APPROVED') THEN 1 ELSE NULL END)` + `UNIQUE` on `barber_name, booking_date, booking_time, active_slot_marker`). `BusySlotsService.getBusySlots()` `@Cacheable sync=true` 2 m reads the active (PENDING/APPROVED only — DENIED and CANCELLED free the slot) bookings via `findActiveForBarberOnDate`; `AppointmentServiceImpl` catches `DataIntegrityViolationException 23505` as DB-enforced second guard (50-way race → exactly 1/49, 808/sec).
- **Redis Caching & Eviction (P0-2 §39)**: `CacheConfig.java` Redis `10m` (`barbers`/`publicBarbers`/`services`, `sync=true` stampede protection: `SingleFlightCacheManager` puts a per-key local lock in front of a cross-replica Redis lease (`SET lock:<cache>:<key> NX`, lease `app.cache.single-flight.lock-lease-ms`=10 s, compare-and-delete release; losers poll and load themselves after `max-wait-ms`=5 s; any Redis error means per-JVM only) — Spring Data Redis' default writer ignores `sync`, typed Jackson 3 value serializers registered per module (`catalog/CatalogCacheConfig`, `appointment/AppointmentCacheConfig` via `CacheConfig.listCache/cache`; no type ids in Redis, so stored data cannot choose a class; an unreadable/old-format value reads as a miss and `RedisBackoffCacheManager` reloads and overwrites it — the Redis writer itself returns stored bytes from `get(key, loader)` without calling the loader; the allow-listed generic Jackson 2 serializer is only the default for a cache without its own configuration), `disableCachingNullValues`) vs `simple` dev, plus `busySlots` at `2m` (`<barber>-<date>` start-minute lists, plus `<barber>-<date>-<minutes>` length-aware lists for services longer than one grid step; `AppointmentStatsService.clearAvailabilityCache` evicts both, using the catalog's durations) and `appointmentStats` at `5m`; `BarberServiceImpl`/`CatalogServiceImpl` `@Cacheable sync=true` + `@CacheEvict(allEntries=true)` on `create/update/delete`; verified: cached `0.6 µs` vs DB `42 µs` (50–90× H2, ~1200× PG). **Caches fail open**: `CacheErrorHandlingConfig` registers `FailOpenCacheErrorHandler` (a failed read runs the method, a failed write/evict is skipped, one rate-limited WARN per 30 s), and `AppointmentStatsService` bypasses the store the same way for its direct cache calls; beneath `SingleFlightCacheManager`, `RedisBackoffCacheManager` skips Redis reads/writes for the `RedisBackoff` interval after a failure (loaders run directly, evictions are always attempted) and shares that back-off with the load lease. `RedisBackoff.allowRequest()` lets exactly **one** caller probe Redis when an interval ends (`isAvailable()` is a non-claiming peek); the rate limiter uses it too and no longer counts `OPTIONS` preflights; prod `spring.data.redis.timeout=250ms` (was 2 s: a hung Redis stalled every request 2–4 s and the cached public endpoints answered only 503) and `spring.data.redis.connect-timeout=1s` (Lettuce's default is 10 s per connection attempt, §61). `appointmentStats` also holds `total-count`, the row count the unfiltered admin listing uses instead of a `COUNT(*)` per request (`findPageWithoutCount`, evicted with the stats).
- **Tiered Cache-Control & ETag (P1-3 §44)**: `CacheControl.maxAge(5, TimeUnit.MINUTES).cachePublic()` for `GET /api/v1/catalog`/`barbers`/`reviews/public/barber-ratings` (5 m public, aligns 10 m `@Cacheable` + `ShallowEtagHeaderFilter` GET-only → `304` after expiry; the filter buffers the whole body, so it skips `/api/v1/appointments/events` and `Accept: text/event-stream` — wrapped, the SSE stream sent nothing at all, `AppointmentEventStreamHttpIntegrationTest` reads it over a real socket), `maxAge(30s).cachePrivate().mustRevalidate()` for `GET /appointments/public/busy-slots` (30 s private), `noCache().cachePrivate().mustRevalidate()` for admin `GET /appointments` & `barbers/admin`; `frontend/nginx.conf` `keepalive 64` (`keepalive_timeout 50s` below Tomcat's 60 s and `keepalive_requests 10000` = `server.tomcat.max-keep-alive-requests`, so nginx retires idle connections first; `nginx-main.conf` `worker_processes 2`, since `auto` counts host cores, not the container limit) + split `js|css` `immutable, max-age=15552000` (6 M hashed bundles, 0 revalidation) vs `ico|gif|jpe?g|png|svg|woff2?` `public, max-age=3600, must-revalidate` (unhashed `public/` assets) + both HTML shells (`index.html`, the prerendered guest landing served for `/`, and `index.csr.html`, the client-rendered shell for every other route and for `/` when an `access_token` cookie is present, so `/` alone also sends `Vary: Cookie`) `no-cache`, revalidated by ETag, so a deploy never leaves a stale shell pointing at removed bundles; the security headers are declared once at server level and merged into these locations with `add_header_inherit merge` (nginx 1.29.3+), and there is no `error_page` (the image ships no `50x.html`, so it turned backend 502/504s into 404s).
- **Micrometer Histograms (P1-5 §46)**: `application-prod.properties` `percentiles-histogram=true` + `slo=50ms,100ms,200ms` → `_bucket{le}` histograms at `/actuator/prometheus`; `p50/p95/p99` via `histogram_quantile` (client-side `percentiles` were dropped: a second structure per series that cannot be aggregated across instances) SLO (≈1–2% cardinality per `[uri,method,status]` series). `management.observations.enable.spring.security=false` (base properties): the per-filter Spring Security observations cost 25–33% of throughput on cached endpoints; HTTP server metrics and traces are unchanged. Buckets end at 10 s (`maximum-expected-value.http.server.requests=10s`; the key is a prefix, so `http.server.requests.active` keeps its own `2h` — capped below its 2 min minimum, every request failed, `ProdHttpServerRequestsHistogramTest`). `management.observations.enable.lettuce=false` likewise: one observation per Redis command (two per cached request) cost 6.5% of catalog CPU, +13% throughput without it; there are no `lettuce_seconds` metrics or Redis child spans. `PropertyKeysMetadataTest` fails on any property key the classpath metadata does not know or has removed (the renamed `sla`, `server.error.*` → `spring.web.error.*`, `management.endpoint.prometheus.enabled` and the `spring.h2.console.*` keys were silently ignored).
- **PgBouncer Ceiling (P2 §50)**: `application-prod.properties` documents Hikari `maximum-pool-size=25` (fixed-size pool: `minimum-idle=25`, HikariCP README; §60) knee curve (`10→3015 RPS`, `25→4128 RPS +37% selected`, `50→4257 RPS +3%`). The deployment is intentionally single-replica; distributed SSE and PgBouncer transaction pooling are future prerequisites for scale-out.
