# Mobile (React Native / Expo)

Navigation, state, session, TLS pinning, builds and query tuning of `mobile/`.

_Detail moved out of [`AGENTS.md`](../../AGENTS.md); the text is unchanged._

- **Mobile**: React Native / Expo / TypeScript — `mobile/`
  - Entry: `mobile/App.tsx`, source: `mobile/src/`
  - Layout (mirrors the web app so the sync workflow stays one-to-one): `src/features/<admin|auth|booking|customer|landing>/` hold a feature's screens, modals, hooks and API calls (`features/booking/BookingScreen.tsx`, `useShopTimeZone.ts`, `features/admin/useNotifications.ts`, …); `src/core/<auth|appointments|catalog|barbers>/` hold the API call plus `use*` hook (or Zustand store) that several features share, like web's `core/`; `src/api/` is only the transport layer (`client.ts`, `contracts.ts`, `publicEndpoints.ts`); `src/components/common/` is the shared UI kit; `navigation/`, `query/`, `theme/`, `types/` and `utils/` stay at the top. Tests stay in `mobile/__tests__/`. Metro watches the hoisted root `node_modules`; `metro/workspaceBlockList.js` derives the app's dependency closure from the lockfile and block-lists the rest (frontend-only packages, about a quarter of the files), `__tests__/workspaceBlockList.test.ts` guards it. A file used by one feature lives in that feature, by two or more in `core/`. Moving a file means updating both `component-map.json` files (`npm run check:component-map`).
  - Navigation: React Navigation (Guest, Customer, and Admin tab navigators inside Root NativeStack).
  - State: TanStack Query (`@tanstack/react-query`) for server state, Zustand (`useAuthStore`) for client state; subscribe with per-field selectors (`useAuthStore(useShallow((s) => ({ ... })))`), never the whole store. **React Compiler** is on (`app.json` `experiments.reactCompiler`; `babel-plugin-react-compiler` comes with `babel-preset-expo`): components are memoised at build time, so follow the Rules of React (no mutation of props/state during render, no ref reads/writes during render — use `useAnimatedValue`/`useState(() => …)`/`useEffectEvent`). The compiler skips a rule-breaking component silently; `__tests__/reactCompiler.test.ts` fails on any bail-out (§61). Metro resolves `react-hook-form` as CommonJS everywhere (`metro.config.js`): its ESM and CJS builds were both bundled. Import icons per set (`import Ionicons from '@expo/vector-icons/Ionicons'`): the `@expo/vector-icons` barrel bundled all 19 icon fonts (4.1 MB of assets) for the one set the app uses. The native splash stays up (`preventAutoHideAsync` in `RootNavigator`) until the stored session is restored and the Ionicons font has loaded (or failed). `metro/zodLocales.js` (mirrored by a Jest `moduleNameMapper`) gives zod's CommonJS barrels an empty `locales` namespace: the ~60 unused locales were 14% of the minified bundle. Never select a locale through `z.locales`/`config()`; import it from `zod/locales` if one is ever needed.
  - Session: the store has `isBootstrapping` (splash, `checkAuth` only — never gate the navigator on login/register pending state, it unmounts the screens that show the error) and `sessionNotice`. The token expiry is stored next to the token; an expired token is dropped *before* a request is sent (`SessionExpiredError`). `src/api/publicEndpoints.ts` is the single method-aware allowlist mirroring the backend `permitAll` rules — public calls never carry the token and a 401 on them does not log out. Logout calls `POST /auth/logout` (best effort, revokes the token server-side) and always clears local state. Booking: the No-Preference sentinel is passed to busy-slots; wizard state resets after success and on blur; past slots are disabled (`utils/time-utils.ts` helpers, `useNow`). TanStack `focusManager` is wired to `AppState` and `onlineManager` to `expo-network` (unknown state = online); queries and mutations use `networkMode: 'always'` with `refetchOnReconnect: true`, so offline requests fail fast to the error/retry states and nothing is queued. Notification polling only runs while the tab is focused, and the polling query passes focus as `subscribed` (a hidden tab neither fetches nor re-renders).
  - TLS pinning (`plugins/withTaskflowTlsPinning.js`): `TASKFLOW_API_SPKI_CA_PINS` are **CA/intermediate** SPKI hashes on both platforms (the old `TASKFLOW_API_SPKI_PINS`, which meant iOS leaf pins, now fails the prebuild so stale leaf values cannot ship silently) (iOS `NSPinnedCAIdentities`, optional leaf-only `TASKFLOW_API_SPKI_LEAF_PINS`); Android `<pin-set expiration>` comes from `pinExpiration` / `TASKFLOW_API_PIN_EXPIRY` (default build date + 365 d; a current and a backup pin are required). A finalized Android mod forces the pinned `networkSecurityConfig` regardless of plugin order and fails the build if a cleartext config would win. `mobile/app.json`/`eas.json` `projectId` is still a placeholder: run `eas init`; `npm run check:eas` fails until then.
  - Security: Native bearer login via `POST /api/v1/auth/mobile/login`, bearer tokens stored via `expo-secure-store` (iOS Keychain / Android Keystore), and no reliance on a native cookie jar. Bearer-only state-changing requests are CSRF-exempt; web cookie requests retain double-submit CSRF protection.
  - Contracts: request and response payloads are validated at the transport boundary (`mobile/src/api/contracts.ts`) with the shared zod schemas from `@taskflow/schemas` — keep the API clients in sync when the contract changes. Follow the repo formatting style (single quotes); mobile has no `.prettierrc`, so do not bulk-run Prettier with defaults.
  - Builds: EAS Build configured via `mobile/eas.json` for Android (APK/AAB) and iOS (Simulator/IPA); `expo-build-properties` enables R8 minification and resource shrinking for Android release builds and disables Fresco's GIF/WebP decoders (`gifEnabled`/`webpEnabled: false`, ~0.8 MB per ABI; the app renders no such images — re-enable before it does). Metro watches only `mobile/` and `shared/` and resolves packages from `mobile/node_modules`. Expo's experimental Metro tree shaking (`EXPO_UNSTABLE_METRO_OPTIMIZE_GRAPH`/`EXPO_UNSTABLE_TREE_SHAKING`, −3.7% bytecode) is on for the EAS `preview` profile and the Detox release builds only; `production` gets it after a green Detox run on both platforms (the flags are not Gradle inputs: rebuild with `--rerun-tasks` after toggling). EAS profiles pin `node` to `.nvmrc` and use the compile cache (`EAS_USE_CACHE`; production saves only). Detox Android release builds `arm64-v8a` only (`DETOX_ANDROID_ABIS` overrides). The nightly `react-native-ci.yml` run executes the Detox suite on both platforms (`android-e2e`: x86_64 emulator on Linux; `ios-e2e`: `macos-26` simulator) against the backend JAR on `localhost:8080` with the default profile (no Docker on macOS runners); nightly or `workflow_dispatch` (never on push/pull request) and outside the required gates. Mobile `tsc` is incremental (`node_modules/.cache/tsconfig.tsbuildinfo`).
- **Mobile Query Tuning (P1-4 §45)**: `mobile/src/query/queryClient.ts` `staleTime 60_000` (was 0, cuts catalog/barbers refetch ~50% on tab nav) + `gcTime 5*60_000` (retain across nav) + exponential `retryDelay min(1000*2^attempt,30000)` `retry:1` `refetchOnWindowFocus:false`; `mobile/src/api/client.ts` `timeout 10000` (was 15000, fail-fast > JPA 5 s + Hikari 4 s worst case).
- **Lookbook Fix (P2 §49)**: `mobile/src/features/landing/LookbookGallery.tsx` replaces `FlatList scrollEnabled={false}` inside parent `ScrollView` (defeats virtualization) with plain `LOOKBOOK_DATA.map` + `View` + `Card`; parent `ScrollView` owns scroll, documented upgrade to `FlashList` when catalogue >50 items. CWV budgets in `k6/browser.js` tightened to `ttfb<800 fcp<1800 lcp<2500` (web.dev good) vs prior lenient `p95<2500 lcp<6000`; remote CI (`k6.yml`) runs with `ENFORCE_CWV=false` because a GitHub runner measures cross-region latency, so the CWV budgets only gate same-region/local runs while the functional wizard checks remain the remote gate.
- **Mobile uses React Native & Expo** with TypeScript, React Navigation, TanStack Query, Zustand, and `expo-secure-store` for hardware token security. Theme colors import from `mobile/src/theme/tokens.json`.
- **Mobile query tuning**: `staleTime 0→60_000` cuts refetch ~50% — but raising further risks showing stale `DENIED` slots; `busySlots` stays `30 s private` for volatility. `timeout 10000` comfortably exceeds the ~9 s server-side worst case (JPA 5 s + Hikari `connection-timeout` 4 s) — don't lower it below that combined ceiling.
