# Mobile (React Native / Expo)

Navigation, state, session, TLS pinning, builds and query tuning of `mobile/`.

_Detail moved out of [`AGENTS.md`](../../AGENTS.md); the text is unchanged._

- **Mobile**: React Native / Expo / TypeScript — `mobile/`
  - Entry: `mobile/App.tsx`, source: `mobile/src/`
  - Layout (mirrors the web app so the sync workflow stays one-to-one): `src/features/<admin|auth|booking|customer|landing>/` hold a feature's screens, modals, hooks and API calls (`features/booking/BookingScreen.tsx`, `useShopTimeZone.ts`, `features/admin/useNotifications.ts`, …). Large screens are thin compositions: `BookingScreen` renders `BookingHeader` and one component per step (`ServiceStep`, `StylistStep`, `DateTimeStep`, `ContactStep`, with `StepNavigation` and `wizardStyles` shared between them) from `useBookingWizard` (selection, step validation, the idempotency key of the attempt, submission), whose rules are pure functions in `bookingWizard.ts` (the clock is passed in, never read); `HomeScreen` stacks section components (`AnnouncementBar`, `HomeHeader`, `HeroSection`, `GroomingMenu` + `ShopInfo`, `MasterStylists`, `FaqSection`, titled by `HomeSection`) that load their own data. Each component keeps its own `StyleSheet`; `src/core/<auth|appointments|catalog|barbers>/` hold the API call plus `use*` hook (or Zustand store) that several features share, like web's `core/`; `src/api/` is only the transport layer (`client.ts`, `contracts.ts`, `publicEndpoints.ts`); `src/components/common/` is the shared UI kit, including UI hooks several features use (`useFlashMessage`: the timed success/error banners of the customer portal, admin dashboard and public actions, one timer per kind, cleared on unmount); `navigation/`, `query/`, `theme/`, `types/` and `utils/` stay at the top. Tests stay in `mobile/__tests__/`. Metro watches the hoisted root `node_modules`; `metro/workspaceBlockList.js` derives the app's dependency closure from the lockfile and block-lists the rest (frontend-only packages, about a quarter of the files), `__tests__/workspaceBlockList.test.ts` guards it. A file used by one feature lives in that feature, by two or more in `core/`. Moving a file means updating both `component-map.json` files (`npm run check:component-map`).
  - Navigation: React Navigation (Guest, Customer, and Admin tab navigators inside Root NativeStack).
  - State: TanStack Query (`@tanstack/react-query`) for server state, Zustand (`useAuthStore`) for client state; subscribe with per-field selectors (`useAuthStore(useShallow((s) => ({ ... })))`), never the whole store. **React Compiler** is on (`app.json` `experiments.reactCompiler`; `babel-plugin-react-compiler` comes with `babel-preset-expo`): components are memoised at build time, so follow the Rules of React (no mutation of props/state during render, no ref reads/writes during render — use `useAnimatedValue`/`useState(() => …)`/`useEffectEvent`). The compiler skips a rule-breaking component silently; `__tests__/reactCompiler.test.ts` fails on any bail-out (§61), and on a `.tsx` or `use*.ts` file in which it compiled nothing (a component it does not recognise, such as an anonymous default export, is skipped without an error; `NOTHING_TO_COMPILE` lists the class component and the Zustand store). Metro resolves `react-hook-form` as CommonJS everywhere (`metro.config.js`): its ESM and CJS builds were both bundled. Import icons per set (`import Ionicons from '@expo/vector-icons/Ionicons'`): the `@expo/vector-icons` barrel bundled all 19 icon fonts (4.1 MB of assets) for the one set the app uses. The native splash stays up (`preventAutoHideAsync` in `RootNavigator`) until the stored session is restored and the Ionicons font has loaded (or failed). `metro/zodLocales.js` (mirrored by a Jest `moduleNameMapper`) gives zod's CommonJS barrels an empty `locales` namespace: the ~60 unused locales were 14% of the minified bundle. The core and mini barrels also get an empty module for the JSON Schema, `compile` and memoizer code they re-export (−2.95% bytecode): never call `toJSONSchema` or `z.core.compile` from mobile code. Never select a locale through `z.locales`/`config()`; import it from `zod/locales` if one is ever needed.
  - Session: the store has `isBootstrapping` (splash, `checkAuth` only — never gate the navigator on login/register pending state, it unmounts the screens that show the error) and `sessionNotice`. The token expiry is stored next to the token; an expired token is dropped *before* a request is sent (`SessionExpiredError`). `utils/storage.ts` keeps an in-memory copy of token and expiry (filled by the first read or a write, dropped by every write/removal and `clearSession`, a read overtaken by a write is not cached), so a protected request does not cross the native bridge; SecureStore remains the persistence layer. Tests that seed the `expo-secure-store` mock directly reset it with `storage.clearSession()` first. `src/api/publicEndpoints.ts` is the single method-aware allowlist mirroring the backend `permitAll` rules — public calls never carry the token and a 401 on them does not log out. Logout calls `POST /auth/logout` (best effort, revokes the token server-side) and always clears local state. Booking: the No-Preference sentinel is passed to busy-slots; busy slots are fetched only from the date/time step on and only for a catalog service (`useBusySlots(…, { enabled })`), and no treatment is selected before the catalog loads (step 1 refuses Continue rather than sending a hard-coded name); wizard state resets after success and on blur; past slots are disabled (`utils/time-utils.ts` helpers, `useNow`). TanStack `focusManager` is wired to `AppState` and `onlineManager` to `expo-network` (unknown state = online); queries and mutations use `networkMode: 'always'` with `refetchOnReconnect: true`, so offline requests fail fast to the error/retry states and nothing is queued. Notification polling only runs while the tab is focused, and the polling query passes focus as `subscribed` (a hidden tab neither fetches nor re-renders). Every `queryFn` forwards TanStack's `signal` to axios (`RequestOptions` in `api/client.ts`), so an unmounted or superseded query aborts its request; paginated lists (`useAppointments`, `useCustomerAppointments`) use `placeholderData: keepPreviousData` (busy slots deliberately not: another day's slots must never show). Mutation hooks invalidate the affected keys, so screens do not `refetch()` after a mutation.
  - Session renewal (ADR-023): `mobile/login` also returns a one-time `refreshToken` (SecureStore `taskflow_refresh_token`, erased by `storage.clearSession()` even when the logout request fails). `api/client.ts` renews before sending a request whose token expired and once after a 401 of a request that **carried** a bearer token, then replays it (any method: Spring rejects the token before a handler runs); only a 401 (or no stored refresh token) ends the session, a network failure, 5xx or unreadable Keychain keeps it (`storage.getRefreshToken()` throws on a read error, never answers "none"). Logout sends the refresh token in its body so the server revokes the family (without it when the Keychain cannot be read: a valid bearer alone revokes it).
  - Session epoch: `storage.getSessionEpoch()` moves at the **call** of `startSession` (login) and `clearSession` (logout, rejection), never on a renewal. Credential batches (`startSession`, `rotateSession`, `clearSession`) run one at a time and reads wait for earlier batches; never write the token, expiry or refresh token one by one. A request stores its epoch in the axios config (`sessionEpoch`, kept by the replay) and `renewSession(epoch)` reads it before the refresh token: once it moved on, a 401 is ignored, nothing is stored, the request is not sent with the newer session's token, and the caller gets `SessionChangedError` (never retried by `shouldRetryQuery`).
  - Calendar export and telemetry: `core/calendar/shareCalendarFile.ts` writes the server's `.ics` to the cache (`expo-file-system`) and shares the **file** (`expo-sharing`, `text/calendar` / `com.apple.ical.ics`), so Calendar imports it; `expo-sharing` is a native module, so the app needs a rebuild (prebuild) after this change. Telemetry (`core/telemetry/appTelemetry.ts`) is off unless the build sets `EXPO_PUBLIC_TELEMETRY_SAMPLE_RATE` (0 < rate ≤ 1); `ErrorBoundary` reports render errors and `installGlobalErrorReporting` uncaught JS errors, never their content.
  - Reschedule and weekly hours: `core/appointments/ReschedulePicker.tsx` (portal and `PublicRescheduleModal`) uses the shared `rescheduleDates`/`openSlotsOn` rules with `useRescheduleAvailability(publicId, date, email?)`, the server's answer for that booking (query key under `busySlots`, so booking mutations refresh it), and shows the server's reason (wrong email, booking no longer movable) with a retry; `PublicRescheduleModal` fixes the verified `{publicId, email}` when the picker opens and closes it when either field is edited. `features/admin/WeeklyHoursEditor.tsx` previews a schedule change, needs confirmation before cancelling bookings and is remounted (`key`) per barber and revision, so a 409 reload starts it from the server's hours; every save attempt also drops the preview and confirmation (`onSettled`, like web), because a 409 for changed bookings reloads the same revision and keeps it mounted.
  - TLS pinning (`plugins/withTaskflowTlsPinning.js`): `TASKFLOW_API_SPKI_CA_PINS` are **CA/intermediate** SPKI hashes on both platforms (the old `TASKFLOW_API_SPKI_PINS`, which meant iOS leaf pins, now fails the prebuild so stale leaf values cannot ship silently) (iOS `NSPinnedCAIdentities`, optional leaf-only `TASKFLOW_API_SPKI_LEAF_PINS`); Android `<pin-set expiration>` comes from `pinExpiration` / `TASKFLOW_API_PIN_EXPIRY` (default build date + 365 d; a current and a backup pin are required). A finalized Android mod forces the pinned `networkSecurityConfig` regardless of plugin order and fails the build if a cleartext config would win. `mobile/app.json`/`eas.json` `projectId` is still a placeholder: run `eas init`; `npm run check:eas` fails until then.
  - Security: Native bearer login via `POST /api/v1/auth/mobile/login`, bearer tokens stored via `expo-secure-store` (iOS Keychain / Android Keystore), and no reliance on a native cookie jar. Bearer-only state-changing requests are CSRF-exempt; web cookie requests retain double-submit CSRF protection.
  - Contracts: request and response payloads are validated at the transport boundary (`mobile/src/api/contracts.ts`) with the shared zod schemas from `@taskflow/schemas` — keep the API clients in sync when the contract changes. Follow the repo formatting style (single quotes); mobile has no `.prettierrc`, so do not bulk-run Prettier with defaults.
  - Builds: EAS Build configured via `mobile/eas.json` for Android (APK/AAB) and iOS (Simulator/IPA); `expo-build-properties` enables R8 minification and resource shrinking for Android release builds and disables Fresco's GIF/WebP decoders (`gifEnabled`/`webpEnabled: false`, ~0.8 MB per ABI; the app renders no such images — re-enable before it does). Metro watches `shared/` and the hoisted root `node_modules` (minus every package the app cannot reach: `metro/workspaceBlockList.js`, one RegExp) and resolves `mobile/node_modules` first. The EAS `preview` APK builds `arm64-v8a,armeabi-v7a` only (`ORG_GRADLE_PROJECT_reactNativeArchitectures`; the x86 emulator ABIs doubled the native build for devices that never install it); `production` (AAB) builds every ABI. Expo's experimental Metro tree shaking (`EXPO_UNSTABLE_METRO_OPTIMIZE_GRAPH`/`EXPO_UNSTABLE_TREE_SHAKING`, −3.7% bytecode) is on for the EAS `preview` profile and the Detox release builds only; `production` gets it after a green Detox run on both platforms (the flags are not Gradle inputs: rebuild with `--rerun-tasks` after toggling). EAS profiles pin `node` to `.nvmrc` and use the compile cache (`EAS_USE_CACHE`; production saves only). Detox Android release builds `arm64-v8a` only (`DETOX_ANDROID_ABIS` overrides). The nightly `react-native-ci.yml` run executes the Detox suite on both platforms (`android-e2e`: x86_64 emulator on Linux; `ios-e2e`: `macos-26` simulator) against the backend JAR on `localhost:8080` with the default profile (no Docker on macOS runners); nightly or `workflow_dispatch` (never on push/pull request) and outside the required gates. Mobile `tsc` is incremental (`node_modules/.cache/tsconfig.tsbuildinfo`).
- **Mobile Query Tuning (P1-4 §45)**: `mobile/src/query/queryClient.ts` `staleTime 60_000` (was 0, cuts catalog/barbers refetch ~50% on tab nav) + `gcTime 5*60_000` (retain across nav) + `retry: shouldRetryQuery` (at most one retry, only for network errors/timeouts, 408 and 5xx; never 4xx, `ApiContractError` or `SessionExpiredError`; 429 only with a `Retry-After` ≤ 10 s) + `retryDelay: queryRetryDelay` (1 s, or the server's `Retry-After`, capped 30 s) + `refetchOnWindowFocus:false` by default, `true` on `useAppointments`/`useCustomerAppointments`/`useBusySlots`/`useNotifications` (focus = app foreground via `focusManager`; refetches only stale data); `mobile/src/api/client.ts` `timeout 10000` (was 15000, fail-fast > JPA 5 s + Hikari 4 s worst case).
- **Lookbook Fix (P2 §49)**: `mobile/src/features/landing/LookbookGallery.tsx` replaces `FlatList scrollEnabled={false}` inside parent `ScrollView` (defeats virtualization) with plain `LOOKBOOK_DATA.map` + `View` + `Card`; parent `ScrollView` owns scroll, documented upgrade to `FlashList` when catalogue >50 items. CWV budgets in `k6/browser.js` tightened to `ttfb<800 fcp<1800 lcp<2500` (web.dev good) vs prior lenient `p95<2500 lcp<6000`; remote CI (`k6.yml`) runs with `ENFORCE_CWV=false` because a GitHub runner measures cross-region latency, so the CWV budgets only gate same-region/local runs while the functional wizard checks remain the remote gate.
- **Mobile uses React Native & Expo** with TypeScript, React Navigation, TanStack Query, Zustand, and `expo-secure-store` for hardware token security. Theme colors import from `mobile/src/theme/tokens.json`.
- **Mobile query tuning**: `staleTime 0→60_000` cuts refetch ~50% — but raising further risks showing stale `DENIED` slots; the `busySlots` response is `no-cache` (revalidated every time), so an invalidation always reaches the server — React Native's own HTTP cache (OkHttp on Android, NSURLCache on iOS) honours `Cache-Control`, see gotchas. `timeout 10000` exceeds the server's worst case for one query (Hikari `connection-timeout` 4 s + JPA query timeout 5 s) — don't lower it below that. It is no whole-request bound: a request running several queries can take longer (see gotchas).
