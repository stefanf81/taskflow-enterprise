  - Runtime Profiles & Multi-Arch JVM Optimization:
    - **One Dockerfile, two targets.** `Dockerfile` has shared `extractor`, `java-base`, `cds-training` and `runtime` stages and two final targets: `prod` (CI, `--target prod`, `platforms: linux/amd64`; per-build Ubuntu package refresh, `curl`/`wget`/`gnupg` purged, setuid bits stripped, no HEALTHCHECK) and `local` (compose `target: local`; `wget` + HEALTHCHECK, no apt layer of its own; the last stage, so also the default target of an untargeted build). tini and `wget` are installed once, in `runtime`, before the application layers, so a new JAR never re-runs apt; neither is version-pinned, so an uncached build can resolve newer ones. `wget` must be installed there: the Java 25 base ships no curl/wget/gnupg, and without it every compose health check fails (§62). Both `apt-get update` calls use `--error-on=any` (by default APT only warns on a failed download, and the prod upgrade would then succeed without those updates; `ContainerImageBenchmarkTest` guards it). `runtime` replaces the base's inherited Ubuntu `title`/`description` OCI labels; the account home is `/nonexistent`. Build `prod` by hand with `docker build --platform linux/amd64 --target prod .`. The target architecture is chosen by the builder, never hardcoded in the file: compose builds for the host, the workflows pass `linux/amd64`; only the extractor stage pins `$BUILDPLATFORM`.
    - **JVM sizing is deployment-owned.** The image CMD (shared `runtime` stage) is sizing-agnostic: it carries only environment-invariant flags (`-XX:AOTCache=application.aot`, `-XX:+ExitOnOutOfMemoryError`). Heap / off-heap / GC behavioral tuning live in `JAVA_TOOL_OPTIONS` of the runtime environment, NOT the image. Setting sizing in the CMD would silently win over the deployment env (JVM last-wins precedence for non-sticky flags) and recreate the precedence bug where the deployment's tuning was a no-op.
    - **Local (Apple Silicon M4 Pro):** the `local` target, built natively for the host architecture, ships only runtime invariants. Heap / off-heap sizing and behavioral GC flags are set via `JAVA_TOOL_OPTIONS` in `docker-compose.yml` (50% × 2560M limit ≈ 1.25 GiB heap, G1GC + AlwaysPreTouch + MaxDirectMemorySize=256m + MaxMetaspaceSize=256m).
    - **Production (AMD Ryzen 5 7430U):** the `prod` target, built by the workflows for `linux/amd64`. The image is sizing-agnostic; JVM sizing is owned by `homelab/TF/gitops/apps/taskflow/backend.yaml` `JAVA_TOOL_OPTIONS`: `MaxRAMPercentage=50.0` (50% × 2Gi = 1 GiB heap, leaving 1 GiB for off-heap), `MaxDirectMemorySize=256m`, `MaxMetaspaceSize=256m`, plus behavioral GC flags (G1GC, `MaxGCPauseMillis=100`, AlwaysPreTouch) and heap-dump-on-OOM. CPU-pinned GC/AVX flags are deliberately omitted so the JVM reads the container's actual CPU allocation.
    - **Healthcheck Divergence (P1-6 §47):** The `local` target carries `HEALTHCHECK --interval=30s --timeout=5s --retries=3 --start-period=60s --start-interval=2s CMD wget -qO /dev/null http://localhost:8080/actuator/health/liveness` for standalone `docker run` & `depends_on: condition: service_healthy`. The `prod` target intentionally omits `HEALTHCHECK` — K8s `livenessProbe`/`readinessProbe` in `homelab/TF/gitops/apps/taskflow/backend.yaml` is the source of truth.
    - **Production manifests live in a separate repo** (`homelab/TF/gitops/apps/taskflow/`), not in this workspace.

## Cross-Platform AI Feature Synchronization Workflow

When modifying or porting a feature between Web (`frontend/`) and Mobile (`mobile/`):
1. **Lookup Component Mapping**: Inspect `frontend/src/component-map.json` or `mobile/src/component-map.json` to identify target files on both platforms.
2. **Use Opencode Sync Skill**: Reference `.opencode/skills/sync-to-mobile.md` for exact framework translation rules:
   * **State**: Angular Signals (`signal()`, `computed()`) $\rightarrow$ TanStack Query (`useQuery`) / Zustand (`useAuthStore`).
   * **Templates**: Angular `@if`/`@for` $\rightarrow$ React Native JSX conditionals & `FlatList`/`map()`.
   * **Theme**: Ensure color tokens originate from the platform-local token files (`mobile/src/theme/colors.ts`).
3. **Sync API Contracts**: If backend endpoints/DTOs change, start the backend, run `npm run api:spec:update`, then `npm run sync:api-types`. Commit the baseline and both generated client type files. Run `npm run sync:api-types:check` before finishing.
4. **Verify**: Run `npm run lint:all` and `npm run test:all`.

### Local AI & Developer Agent Stack (LM Studio & Opencode)

To maintain absolute data privacy, cost efficiency, and low-latency development iteration, the coding agents are backed by a local, high-performance LLM stack run via **LM Studio** and orchestrated by **Opencode**.

*   **Primary Reasoning Model:** Qwen 35B MTP (`qwen3.6-35b-a3b-mtp`), loaded with native Multi-Token Prediction (MTP) speculative decoding for extremely high inference speeds.
*   **API Protocol:** OpenAI-compatible local endpoint on `http://localhost:1234/v1`.
*   **UI Integration & Collapsible Thoughts:** The model is configured inside `~/.config/opencode/opencode.jsonc` with `"reasoning": true` to separate internal `<think>` reasoning strings from the final coding outputs. Opencode renders these steps in native collapsible panels.
*   **Credentials Hardening:** Plaintext API keys or tokens are banned in configurations. The GitHub Personal Access Token is dynamically injected via Opencode's env substitution: `"GITHUB_PERSONAL_ACCESS_TOKEN": "{env:GITHUB_PERSONAL_ACCESS_TOKEN}"`.
*   **Configuration Backups:** 
    - Opencode LLM parameters: Saved in `llm-config.json` (external to repo)
    - LM Studio Model loading parameters: Saved in `lmstudio-qwen-config.json` (external to repo)

## Key Conventions

- **DB**: H2 in dev/test, PostgreSQL in prod (docker-compose / K8s). Flyway handles migrations — never use `ddl-auto=update`. All profiles use `ddl-auto=validate`.
- **Container Hardening & Zero-Trust**:
  - **Numeric UIDs**: Backend containers are configured with a hardcoded, unprivileged numeric UID (`10001:10001`) to comply with strict Kubernetes Pod Security Standards (PSS).
  - **Zero-Trust Networks**: `docker-compose.yml` isolates the DB and Cache on the `backend-tier` network. The Nginx reverse proxy is on the `frontend-tier`. The backend bridges both. The frontend cannot physically talk to the database.
  - **Read-Only Root**: Application containers (`backend`, `frontend`) mount read-only filesystems with ephemeral directories mounted as `tmpfs` (e.g., `/tmp`, `/var/cache/nginx`), preventing runtime binary tampering.
  - **Dropped Capabilities**: Edge application containers completely drop kernel privileges (`cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`); datastores (`db`, `redis`, `jaeger`) use standard container defaults.
  - **Container Lifecycle**: `docker-compose.yml` uses `restart: "no"` so containers do not linger across system/Docker reboots. Verification and E2E scripts (`./verify.sh`, `npm run e2e:docker`) use exit traps (`./stop-docker.sh`) to automatically stop containers after test completion.
  - **Graceful Shutdown**: Spring drains for 30 seconds (`server.shutdown=graceful`, `spring.lifecycle.timeout-per-shutdown-phase=30s`) and the Compose backend has a 40-second `stop_grace_period`. Keep production `terminationGracePeriodSeconds` longer than the Spring shutdown phase in the separate GitOps repository.
- **OSIV is off** (`spring.jpa.open-in-view=false`) — connections return to Hikari pool immediately after service methods.
- **Bounded Async Executor (P0-1 §38)**: `core/AsyncConfig.java` replaces Spring's unbounded `@EnableAsync` default (`core=8 max=Integer.MAX_VALUE queue=Integer.MAX_VALUE`) with bounded `ThreadPoolTaskExecutor` `core=8 max=64 queue=100 CallerRunsPolicy` (`taskflow-async-` 30 s graceful) — burst backpressures caller instead of OOMing the 1.25 GiB heap.
- **Partial Unique Slot Index (P0-4 V21/V25 §41)**: `db/migration/V21__fix_double_booking_index.java` introduces the PostgreSQL partial index `idx_appointment_slot_active ON appointments(barber_name, booking_date, booking_time) WHERE status IN ('PENDING','APPROVED')`, with a plain 4-column unique index (adding `status`) as V21's own H2 fallback. `V25__converge_appointment_slot_index.java` later reconciles both migration paths onto the same semantics and upgrades the H2 fallback to a generated-column emulation of the partial index (`active_slot_marker INTEGER AS (CASE WHEN status IN ('PENDING','APPROVED') THEN 1 ELSE NULL END)` + `UNIQUE` on `barber_name, booking_date, booking_time, active_slot_marker`). `BusySlotsService.getBusySlots()` `@Cacheable sync=true` 2 m reads the active (PENDING/APPROVED only — DENIED and CANCELLED free the slot) bookings via `findActiveForBarberOnDate`; `AppointmentServiceImpl` catches `DataIntegrityViolationException 23505` as DB-enforced second guard (50-way race → exactly 1/49, 808/sec).
- **No-Preference Assignment (ADR-014)**: `No Preference (First Available)` is input-only; `BusySlotsService.findFirstAvailableBarber()` (uncached) resolves it to a scheduled, non-time-off, free barber inside the booking transaction, and the concrete `barberName`/`barber` FK are persisted. Never store the sentinel — the partial index cannot protect a fictitious barber name. `V26__assign_sentinel_appointments.java` repairs legacy rows (assign first eligible barber, else `DENIED`). No barber available → 400.

- **Booking rules (one rule set, `BusySlotsService.evaluate`)**: used by create, admin approve and No-Preference resolution. `bookingTime` must be one of `ALL_SLOTS` (hourly grid), inside the barber's schedule, `start + service duration <= closing`, and must not overlap any PENDING/APPROVED booking of that barber/date (existing bookings count with their own service duration; a legacy row without a service counts as 60 min). - **Compose datastores (§59)**: `db` has `shm_size: 256mb` (parallel hash joins failed at Docker's 64 MB `/dev/shm`) and a TCP `pg_isready -h 127.0.0.1` probe (the init server listens on the socket only); Redis runs without `--io-threads` (1 CPU: threads raised p50 latency and cut throughput up to 45%). PostgreSQL uses `wal_compression=lz4` (cheapest of pglz/lz4/zstd at ~70% less WAL). Jaeger keeps `max_traces: 20000` with `GOMEMLIMIT=200MiB` inside its 256M limit; Jaeger 2.22 enables MCP with an `ai: mcp: {}` block (the old `enable_mcp` key fails validation and Jaeger exits). Every health check has `start_period` + `start_interval`, so `depends_on: service_healthy` follows the real boot time.

## Gotchas

- `./gradlew test` runs the Docker-independent H2 test suite. Use
  `./gradlew testcontainersTest` for the tagged PostgreSQL/Testcontainers suite;
  that task requires Docker.
- Full `./verify.sh` also requires `psql` on `PATH` for the migration-preparation script tests. Homebrew's `libpq` is keg-only: use `PATH="$(brew --prefix libpq)/bin:$PATH" ./verify.sh` after installing it.
- On macOS Rancher Desktop (`unix://…/.rd/docker.sock`), `verify.sh` sets `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock` for Ryuk unless already explicitly set. Direct Gradle invocations need that environment override too; do not disable Ryuk or change the host Docker endpoint to fix the VM mount.
- `./gradlew check` does not run OWASP dependency checking. Run `./gradlew dependencyCheckAnalyze` explicitly when needed (fails on CVSS >= 7).
- Container-config guards (`@Tag("container-config")`: `ContainerImageBenchmarkTest`, `GlibcTuningBenchmarkTest`, `ContainerConfigGuardTest`) are excluded from `test` and run in `containerConfigTest`, which declares the files they read as inputs. A new guard that reads another file must add it to that task's `inputs.files` (and, if it is a workflow, to CI's `docker_backend` filter).
- The `.env` file (from `.env.example`) is required by docker-compose and is git-ignored — copy `.env.example` to `.env` and adjust as needed. Change default passwords before production use.
- Frontend `dist/` and `node_modules/` are gitignored. Do not commit build artifacts.
- E2E tests (`npm run e2e`) start their own dev server — don't run `npm start` separately when running e2e.
- **PgBouncer ceiling**: The current deployment is one replica against PostgreSQL `max_connections=50`. Security and cache state is replica-safe (`app.state.store=redis`), but do not add replicas until admin SSE appointment events are distributed and PgBouncer transaction pooling (or pool × replicas < 50) is in place.
- **Cache eviction is verified, not assumed**: `barbers`/`publicBarbers`/`services` (`10 m`) & `busySlots` (`2 m`) use `@CacheEvict(allEntries=true)` on `create/update/delete`; `ReferenceDataCacheBenchmarkTest` asserts `200→201` after mutation. Don't add L2/Hib query cache without re-testing.
- **Cache-Control ↔ @Cacheable alignment**: Changing tiered headers (`5 m public` catalog/barbers/ratings, `30 s private` busySlots, `no-cache private` admin) must keep `10 m` `@Cacheable` and `ShallowEtagHeaderFilter` (GET-only) in sync — otherwise `304`/`TTL` mismatches cause stale or over-fetch.
- **HEALTHCHECK divergence**: Don't add `HEALTHCHECK` to the Dockerfile's `prod` target or to a stage it inherits from (`runtime`, `java-base`) — K8s `livenessProbe` owns prod; the `local` target keeps it for `docker run` & `depends_on: service_healthy` (`ContainerConfigGuardTest` asserts presence/absence).
- **Mobile query tuning**: `staleTime 0→60_000` cuts refetch ~50% — but raising further risks showing stale `DENIED` slots; `busySlots` stays `30 s private` for volatility. `timeout 10000` comfortably exceeds the ~9 s server-side worst case (JPA 5 s + Hikari `connection-timeout` 4 s) — don't lower it below that combined ceiling.
- **UseContainerSupport is explicit**: `JAVA_TOOL_OPTIONS` carries `UseContainerSupport` + `HeapDumpOnOutOfMemoryError` + `gc.log` in both `docker-compose.yml` and `homelab/TF` — sizing lives in env, not image CMD (last-wins precedence bug).
- **Default-profile startup must stay offline**: the AOT cache training run boots the real app under `--network=none`, so a startup-time call to an external service (or a bean that needs PostgreSQL/Redis to refresh) fails the image build. The `prod` target has no `curl`/`wget` — K8s probes must be `httpGet`, and debugging uses `kubectl debug`.
